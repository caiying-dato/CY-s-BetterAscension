# 04 · 调试与验证工作流

本文是本次开发中**真正把 bug 找出来**的那套方法。
核心思想：**把"猜"换成"验"，把"静默失败"换成"大声报错"。**

---

## 1. 日志

### 1.1 位置与用法

```
%APPDATA%\SlayTheSpire2\logs\godot.log          ← 最近一次
%APPDATA%\SlayTheSpire2\logs\godot<时间戳>.log   ← 每次启动另存一份
```

实时跟踪：

```powershell
Get-Content "$env:APPDATA\SlayTheSpire2\logs\godot.log" -Wait -Tail 40
```

只筛自己的模组：

```powershell
$f = "$env:APPDATA\SlayTheSpire2\logs\godot.log"
Select-String -Path $f -Pattern "\[MyMod\]" | ForEach-Object { $_.Line }
```

### 1.2 值得记住的日志锚点

| 日志行 | 含义 |
| --- | --- |
| `Found mod manifest file <path>` | 游戏**发现**了你的模组 |
| `Loading assembly DLL <path>` | DLL 被加载 |
| `Loading Godot PCK <path>` | 资源包被挂载 |
| `Calling initializer method of type <T>` | 进入你的 `[ModInitializer]` |
| `Finished mod initialization for '<name>'` | 初始化结束 |
| `Found loc table from mod: <lang> <file>. Merging with base loc table` | 某张本地化表被合并 |
| `Encountered error on game startup!` | **启动被异常中止**，后面跟堆栈 |
| `Skipping loading mod X, it is set to disabled in settings` | 模组被玩家禁用 |

### 1.3 用日志做排除法

我这次能快速定位"精英没加力量"，靠的就是**上一版主动加的诊断行**：

```
Ascension 11 elite check: '…CORPSE_SLUG.name' skipped (not an elite room; mapPoint=Monster, room=Monster).
Ascension 11 elite check: '…TOADPOLE.name'   skipped (not an elite room; mapPoint=Monster, room=Monster).
[INFO] Creating NCombatRoom with mode=ActiveCombat encounter=TERROR_EEL_ELITE.
[ERROR] Failed to apply … NullReferenceException … ToMutable
```

这三行同时证明了：
① 补丁装上了；② 房间判定是对的；③ 钩子确实触发了 —— **问题被压缩到"赋值那一步"**。

如果没加这些日志，就得从"补丁到底装没装上"开始猜。

## 2. IL 校验器 ★

**用途**：Transpiler（改 IL 的补丁）改对没有、有没有漏。
这是本次最有价值的工具——它抓出过一个编译器完全看不出来的真实 bug：
**声称改了 9 处，实际只改对 3 处，另 2 处压根没匹配上**（那 2 处会让进阶 11 在读档时被夹回 10）。

**原理**：不启动游戏，直接把补丁里的"重写逻辑"跑在**真实 `sts2.dll` 的方法体 IL** 上，
用 `MethodBase.GetMethodBody().GetILAsByteArray()` 反汇编，然后断言"目标常量全部被替换、0 残留"。

**为什么不能直接调用补丁方法**：补丁类会初始化游戏自己的 `Logger`，在 Godot 进程外会崩。
所以校验器里**复刻一遍相同的重写算法**——算法短且只依赖 `CodeInstruction` 的 opcode/operand，复刻是可靠的。

放在 `tools/TranspilerCheck/`：

```csharp
// Source/Program.cs —— 关键片段（完整可运行版见参考工程）
using System.Reflection;
using System.Reflection.Emit;
using HarmonyLib;

var dataDir = @"<游戏>\data_sts2_windows_x86_64";
AppDomain.CurrentDomain.AssemblyResolve += (_, e) => {           // 让 sts2 的依赖能被解析
    var p = Path.Combine(dataDir, new AssemblyName(e.Name).Name + ".dll");
    return File.Exists(p) ? Assembly.LoadFrom(p) : null;
};
var game = Assembly.LoadFrom(Path.Combine(dataDir, "sts2.dll"));

// 1) 反汇编：把字节码变成 (opcode, operand)
var map = new Dictionary<ushort, OpCode>();
foreach (var f in typeof(OpCodes).GetFields(BindingFlags.Public | BindingFlags.Static)) {
    var op = (OpCode)f.GetValue(null)!;
    map[(ushort)op.Value] = op;
}
List<CodeInstruction> Disasm(MethodBase m) {
    var il = m.GetMethodBody()!.GetILAsByteArray()!;
    var list = new List<CodeInstruction>();
    int i = 0;
    while (i < il.Length) {
        ushort code = il[i++];
        if (code == 0xFE) code = (ushort)(0xFE00 | il[i++]);
        var op = map[code];
        object? operand = null; int size = 0;
        switch (op.OperandType) {           // 只解析我们关心 operand 的那些
            case OperandType.InlineNone: break;
            case OperandType.ShortInlineI: operand = (sbyte)il[i]; size = 1; break;
            case OperandType.InlineI:      operand = BitConverter.ToInt32(il, i); size = 4; break;
            case OperandType.ShortInlineVar: operand = (int)il[i]; size = 1; break;
            case OperandType.InlineVar:    operand = (int)BitConverter.ToUInt16(il, i); size = 2; break;
            case OperandType.InlineString: { int t=BitConverter.ToInt32(il,i); size=4; try{operand=m.Module.ResolveString(t);}catch{} break; }
            case OperandType.InlineMethod: case OperandType.InlineField:
            case OperandType.InlineType:   case OperandType.InlineTok:
                { int t=BitConverter.ToInt32(il,i); size=4; try{operand=m.Module.ResolveMember(t);}catch{} break; }
            case OperandType.ShortInlineBrTarget: operand = new object(); size = 1; break;   // 分支目标不关心
            case OperandType.InlineBrTarget:      operand = new object(); size = 4; break;
            case OperandType.InlineSwitch: { var n=BitConverter.ToInt32(il,i); size=4+n*4; operand=new object(); break; }
            case OperandType.ShortInlineR: size = 4; break;
            case OperandType.InlineR:      size = 8; break;
            default: size = 4; break;
        }
        i += size;
        list.Add(new CodeInstruction(op, operand));
    }
    return list;
}

// 2) 复刻补丁的重写算法
const sbyte VanillaCeiling = 10, Ceiling = 11;
bool IsCeiling(CodeInstruction ci) =>
    ci.opcode == OpCodes.Ldc_I4_S ? ci.operand is sbyte s && s == VanillaCeiling
                                  : ci.opcode == OpCodes.Ldc_I4 && ci.operand is int v && v == VanillaCeiling;
(int rewritten, List<CodeInstruction> result) Rewrite(IEnumerable<CodeInstruction> src) {
    var outp = new List<CodeInstruction>(); int n = 0;
    foreach (var ci in src) {
        if (IsCeiling(ci)) {
            var repl = new CodeInstruction(OpCodes.Ldc_I4_S, Ceiling);
            repl.labels.AddRange(ci.labels);          // 保留标签，分支目标才不失效
            outp.Add(repl); n++; continue;
        }
        outp.Add(ci);
    }
    return (n, outp);
}

// 3) 断言
void Check(string typeName, string methodName) {
    var t = game.GetType(typeName)!;
    var m = t.GetMethods(BindingFlags.Public|BindingFlags.NonPublic|BindingFlags.Instance|BindingFlags.Static)
             .First(x => x.Name == methodName && x.GetMethodBody() is not null);
    var (n, outp) = Rewrite(Disasm(m));
    int left = outp.Count(IsCeiling);
    Console.WriteLine($"{methodName,-32} rewritten {n} | 10s left {left} | {(left == 0 && n > 0 ? "OK" : "** CHECK **")}");
}

Check("MegaCrit.Sts2.Core.Saves.ProgressState", "ClampAscension");
Check("MegaCrit.Sts2.Core.Saves.ProgressState", "ClampCharacterStatsFields");
Check("MegaCrit.Sts2.Core.Saves.Managers.ProgressSaveManager", "IncrementSingleplayerAscension");
Check("MegaCrit.Sts2.Core.Saves.Managers.ProgressSaveManager", "IncrementMultiplayerAscension");
Check("MegaCrit.Sts2.Core.DevConsole.ConsoleCommands.UnlockConsoleCmd", "UnlockAscensions");
```

期望输出（`10s left` 必须为 0）：

```
ClampAscension                   rewritten 3 | 10s left 0 | OK
ClampCharacterStatsFields        rewritten 6 | 10s left 0 | OK
IncrementSingleplayerAscension   rewritten 1 | 10s left 0 | OK
IncrementMultiplayerAscension    rewritten 1 | 10s left 0 | OK
UnlockAscensions                 rewritten 2 | 10s left 0 | OK
```

## 3. `.pck` 内容断言

本地化目录名写错是**完全静默**的失败（界面显示原始 key）。用部署脚本兜住：

```powershell
$pck  = Join-Path $modDir 'MyMod.pck'
$text = [System.Text.Encoding]::UTF8.GetString([System.IO.File]::ReadAllBytes($pck))
foreach ($expected in @('MyMod/localization/eng/ascension.json','MyMod/localization/zhs/ascension.json')) {
    if ($text.Contains($expected)) { Write-Host "  OK  $expected" }
    else { throw "pck 缺少 $expected —— 检查 csproj 的 <ResourcesDir> 是否等于模组 id" }
}
```

粗但极其有效：`.pck` 里路径字符串是明文，直接搜就行。

## 4. 让失败变可见（最重要的习惯）

**每个补丁都要有"失败可诊断"的路径。** 反面教材：

```csharp
// ❌ 静默失败：匹配不到就什么也不做，你以为生效了，其实没有
var m = new CodeMatcher(instructions);
m.MatchStartForward(CodeMatch.LoadsConstant(10));
m.RemoveInstruction().InsertAndAdvance(new CodeInstruction(OpCodes.Ldc_I4_S, (sbyte)11));
```

正面写法：

```csharp
// ✅ 匹配不到 → 明确 warn；匹配到 → 报告改了几处
match(matcher);
if (matcher.IsInvalid) {
    matcher.Start();
    Log.Warn($"Could not find the ceiling literal at '{site}'; that spot keeps the vanilla limit.");
    return;
}
// …替换…
Log.Info($"Raised {n} ceiling literal(s) to {Ceiling} in '{site}'.");
```

同类习惯：

| 场景 | 做法 |
| --- | --- |
| 接口可能改名 | 用 `AccessTools.TypeByName("全名")` 探测，找不到就 `Log.Error` 并给出候选列表 |
| 枚举/属性可能改名 | 找不到时把**实际可用的成员名**打进日志：`DescribeMembers(type)` |
| 反射调用可能抛 | 包 try/catch，异常带上下文（哪个类型、哪个参数） |
| 钩子可能没触发 | 在决策分支打**限量的**诊断行（如最多 12 行），既能确认活着又不刷屏 |
| 关键效果被应用 | **回读并打出来**：`(now {creature.GetPower<StrengthPower>()?.Amount})`，这行本身就是断言 |

> 最后一条特别值：日志写 `granted 1 Strength (now 1)` 才叫验证过；
> 只写 `called Apply` 只是"没报错"，两者差别在这次开发中是决定性的。

## 5. 用反射/IL 查内部结构

### 5.1 基本套路

```powershell
cd tools\ApiDump
# 改 Source/Program.cs 里的 Dump("类型全名")
dotnet run -c Release
```

骨架（关键是 `AssemblyResolve`，否则 `GetTypes()` 会因缺依赖大面积抛异常）：

```csharp
var dataDir = @"<游戏>\data_sts2_windows_x86_64";
AppDomain.CurrentDomain.AssemblyResolve += (_, e) => {
    var p = Path.Combine(dataDir, new AssemblyName(e.Name).Name + ".dll");
    return File.Exists(p) ? Assembly.LoadFrom(p) : null;      // 找不到返回 null 而不是抛
};
var asm = Assembly.LoadFrom(Path.Combine(dataDir, "sts2.dll"));

void Dump(string fullName) {
    var t = asm.GetType(fullName);
    if (t is null) { Console.WriteLine($"NOT FOUND {fullName}"); return; }
    Console.WriteLine($"### {t.FullName} : {t.BaseType?.FullName}  enum={t.IsEnum} abstract={t.IsAbstract}");
    if (t.IsEnum) { foreach (var v in Enum.GetNames(t)) Console.WriteLine($"  {v} = {Convert.ToInt64(Enum.Parse(t, v))}"); return; }
    foreach (var m in t.GetMethods(BindingFlags.Public|BindingFlags.NonPublic|BindingFlags.Instance
                                 | BindingFlags.Static|BindingFlags.DeclaredOnly)
                       .Where(m => !m.IsSpecialName).OrderBy(m => m.Name))
        Console.WriteLine($"  {m.Name}({string.Join(", ", m.GetParameters().Select(p => p.ParameterType.Name + " " + p.Name))})"
                          + $" -> {m.ReturnType.Name}{(m.IsStatic ? " [static]" : "")}{(m.IsPublic ? "" : " [nonpublic]")}");
    foreach (var f in t.GetFields(BindingFlags.Public|BindingFlags.NonPublic|BindingFlags.Instance
                                | BindingFlags.Static|BindingFlags.DeclaredOnly))
        Console.WriteLine($"  field {f.Name} : {f.FieldType.Name}{(f.IsStatic ? " [static]" : "")}"
                          + $"{(f.IsLiteral ? " [const]" : "")}");
}
Dump("MegaCrit.Sts2.Core.Entities.Ascension.AscensionManager");
```

**注意 `BindingFlags.DeclaredOnly`**：不加会把 `object` 的成员也列出来，噪音很大。

### 5.2 找出"谁读写了某个成员"

这是找"唯一收口点"的核心手法（坑 3 就是靠它解决的）：

```csharp
var target = asm.GetType("MegaCrit.Sts2.Core.Saves.CharacterStats")!
                .GetProperty("MaxAscension")!.GetGetMethod(true)!;

foreach (var t in asm.GetTypes())
foreach (var m in t.GetMethods(BindingFlags.Public|BindingFlags.NonPublic|BindingFlags.Instance
                             | BindingFlags.Static|BindingFlags.DeclaredOnly)) {
    var b = m.GetMethodBody(); if (b is null) continue;
    var il = b.GetILAsByteArray()!;
    for (int i = 0; i < il.Length - 4; i++) {
        if (il[i] != 0x28 && il[i] != 0x6F) continue;      // call / callvirt
        try {
            if (m.Module.ResolveMember(BitConverter.ToInt32(il, i + 1)) == target) {
                Console.WriteLine($"  {t.FullName}.{m.Name}"); break;
            }
        } catch { }
    }
}
```

同理可扫 `newobj`(0x73) 找构造点、`ldfld/stfld`(0x7B/0x80) 找字段读写、
`ldstr`(0x72) 找字符串引用。

### 5.3 读一个方法的完整 IL

`tools/ApiDump/Source/Program.cs` 里有完整的反汇编函数（见 §2 的 `Disasm`，
再加上 `OperandType.InlineMethod/Field` 的 `ResolveMember` 就能显示调用了谁）。
用它我确认了：
- `AscensionManager.maxAscensionAllowed` 的 `IsLiteral=True`
- `AscensionHelper.GetKey(11)` 就是 `"LEVEL_" + level.ToString("D2")`
- `MonsterModel.AfterAddedToRoom` 基类只是 `Task.CompletedTask`
- `MechaKnight` 在同一个钩子里 `await PowerCmd.Apply<ArtifactPower>(..., 3, ...)`

## 6. 标准改动流程

改任何补丁，按这个顺序走：

```
1. dump 确认目标
   └─ 签名对不对？IsLiteral？谁调用它？（tools/ApiDump）
2. 写补丁，带失败日志
   └─ 匹配不到必须 Warn/Error，不能静默
3. 编译
   └─ dotnet build（注意别覆盖 mods 里被锁的 dll）
4. 【改 IL 的补丁】跑校验器
   └─ dotnet run --project tools/TranspilerCheck
   └─ 断言：改了 N 处、剩 0 处
5. 发布 + 部署
   └─ 先确认游戏已退出！deploy.cmd
6. 断言 .pck 内容
   └─ 脚本自动做
7. 进游戏，看日志
   └─ 搜 [ModId]；确认无 ERROR，且有你要的"成功证据行"
```

**第 4 步是最容易被跳过、也最值钱的一步。** 它把"进游戏试 5 分钟"压缩成"跑脚本 3 秒"，
而且能发现"部分生效"这种在游戏里很难察觉的问题。

## 7. 调试决策树

```
游戏启动失败
├─ 日志有 "Encountered error on game startup!"
│  └─ 看它下面的堆栈，找第一个属于你的帧 → 通常是你在初始化里抛了异常
│     （尤其 ModelDb.Init 的 postfix：任何异常都会中止启动）
└─ 日志根本没有你的模组
   └─ "Found mod manifest file" 有没有？
      ├─ 没有 → 路径不对（mods/<ModId>/<ModId>.json）
      └─ 有   → 看 "Skipping loading mod … disabled"

模组加载了但功能没生效
├─ 先确认补丁装上没 → 搜 "Patched <你的补丁类> (N method(s))"
├─ 确认钩子触发没   → 你的诊断行有没有出现
├─ 确认逻辑条件满足没 → 把相关状态值都打出来（坑 3）
└─ 确认动作真的做了没 → 回读并打印结果（"now 1"）

游戏卡死 / 无响应
└─ 几乎一定是：主线程里同步等待异步（.GetResult()/.Wait()/.Result）
   或死循环（怀疑某钩子被递归触发）
   → 看日志停在哪个场景，那里就是死锁点

界面显示原始 key（xxx.title）
└─ 100% 是本地化查不到该 key
   ├─ "Loading Godot PCK" 有没有 → 没有就是 .pck 没生成/没部署
   └─ "Found loc table from mod: <lang> ascension.json" 有没有 → 没有就是目录名/路径不对
```
