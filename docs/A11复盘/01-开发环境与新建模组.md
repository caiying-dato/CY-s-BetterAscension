# 01 · 开发环境与新建模组

本文面向**从零开始做一个改游戏逻辑的 STS2 模组**（不是做卡牌/角色的内容模组）。
所有路径与本机实测一致；装在不同位置时按注释替换。

---

## 1. 需要装什么

| 依赖 | 版本要求 | 本机位置 | 用途 |
| --- | --- | --- | --- |
| **.NET SDK 9** | 9.0.x | `C:\Users\Tao\.dotnet` | 游戏是 `net9.0`，必须用 9 的 SDK |
| **MegaDot** | 必须 `4.5.1` | `C:\Users\Tao\megadot\MegaDot_v4.5.1-stable_mono_win64.exe` | Mega Crit 的 Godot 分支，**只在打 `.pck` 时用** |
| **Slay the Spire 2** | `v0.111.0` | `D:\Program Files (x86)\Steam\steamapps\common\Slay the Spire 2` | 提供 `sts2.dll` / `0Harmony.dll` |
| **BaseLib** | `3.4.7` | 创意工坊 `3737335127\BaseLib\` | 提供 `[CustomEnum]`、本地化工具等 |

### 1.1 为什么必须单独装 .NET 9 SDK

本机系统 `dotnet` 只有 SDK **8.0.405**，而工程要 `net9.0`，直接编译会报：

```
error NETSDK1045: 当前 .NET SDK 不支持面向 .NET 9.0
```

注意"只装运行时不够"——运行时即使有 9.0.7，**没有 SDK 仍然编译不了**。

**安装方式（本机执行策略禁止跑 `.ps1`，所以要绕开官方安装脚本）：**

```powershell
# dotnet-install.ps1 会被执行策略拦下，直接下 zip 解压
$ver = "9.0.306"
$zip = "$env:TEMP\dotnet-sdk-$ver-win-x64.zip"
curl.exe -sSL --max-time 900 -o $zip "https://builds.dotnet.microsoft.com/dotnet/Sdk/$ver/dotnet-sdk-$ver-win-x64.zip"
Expand-Archive -Path $zip -DestinationPath "$env:USERPROFILE\.dotnet" -Force
& "$env:USERPROFILE\.dotnet\dotnet.exe" --list-sdks   # 应看到 9.0.306
```

然后在 `Directory.Build.props` 里把 MSBuild 指过去（否则 `dotnet build` 仍会用系统的 SDK 8）：

```xml
<LocalDotnetRoot Condition="'$(LocalDotnetRoot)' == ''">$(USERPROFILE)\.dotnet</LocalDotnetRoot>
<NetCoreTargetingPackRoot Condition="'$(NetCoreTargetingPackRoot)' == ''">$(LocalDotnetRoot)\packs</NetCoreTargetingPackRoot>
```

调用时带上环境变量：

```powershell
$env:DOTNET_ROOT = "$env:USERPROFILE\.dotnet"
dotnet build .\MyMod.csproj -c Debug
```

### 1.2 MegaDot 下载地址（官方页面是 JS 渲染的）

`https://megadot.megacrit.com/` 页面上的下载列表是 fetch 出来的，直接抓 HTML 拿不到链接。
它背后的目录 API 是可用的：

```powershell
# 列出所有版本
curl.exe -sS "https://megadot.megacrit.com/api/" | ConvertFrom-Json | Where-Object type -eq 'directory'
# 列出某个版本的文件（Windows 版约 578 MB）
curl.exe -sS "https://megadot.megacrit.com/api/4.5.1-m.14/" | ConvertFrom-Json
# → megadot-4.5.1-m.14-windows-x86_64-llvm-editor-csharp.zip
```

> **Godot 版本必须和游戏一致（4.5.1）**，否则游戏不加载你的 `.pck`。同时**不需要**装导出模板
> （`--export-pack` 打纯资源包用不到）。

## 2. 工程骨架

```
MyMod/
├─ MyMod.sln / MyMod.csproj        # Godot.NET.Sdk 工程
├─ MyMod.json                      # 模组清单（id 必须等于工程名）
├─ MyMod/                          # ★ 要打进 .pck 的资源；目录名必须等于模组 id
│  └─ localization/zhs/*.json
├─ Code/
│  ├─ MyModEntry.cs                # [ModInitializer]
│  └─ Patches/*.cs
├─ Directory.Build.props           # .NET 9 路径、GodotPath
├─ local.props(.template)          # 本机路径（git 忽略）
├─ Sts2PathDiscovery.props         # 自动定位游戏安装目录
├─ project.godot
├─ export_presets.cfg
└─ deploy.cmd / deploy.ps1         # 编译+打包+安装+断言
```

### 2.1 ★ 资源目录名是**有约束的**，不是随便起的

这是本次最隐蔽的一个坑。游戏通过 `ModManager.GetModdedLocTables` 找模组文本，
路径是**写死的字符串拼接**（IL 实录）：

```
res:// + <manifest.id> + "/localization/" + <language> + "/" + <file>
```

所以：

| 目录名 | 结果 |
| --- | --- |
| `MyMod/localization/zhs/foo.json` | ✅ 能加载，表名 = `foo` |
| `MyModResources/localization/zhs/foo.json` | ❌ 永远找不到（很多模组这么做，但那是它们自己的约定巧合） |

所以 `csproj` 里要这么写，并且**让 id 与目录名保持一致**：

```xml
<PropertyGroup>
  <ResourcesDir>MyMod</ResourcesDir>       <!-- 必须等于 <AssemblyName> / manifest id -->
  <PckPackerSourceDir>$(ResourcesDir)/</PckPackerSourceDir>
</PropertyGroup>
<ItemGroup>
  <Compile Remove="$(ResourcesDir)/**" />
  <EmbeddedResource Remove="$(ResourcesDir)/**" />
</ItemGroup>
```

并在部署脚本里**断言产物内容**（见 [04](04-调试与验证工作流.md#3-pck-内容断言)），否则这个错误是完全静默的：
游戏不报错，只是把界面上的文字显示成 `LEVEL_11.title` 这样的原始 key。

### 2.2 `project.godot` 与 `export_presets.cfg`

`export_presets.cfg` **手写容易出错**，本机踩到的报错是：

```
warning : Invalid export preset name: BasicExport.
```

原因是手写的预设缺字段（`platform` / `patches` / `seed` / `[preset.0.options]` 里的完整项）。
**最省事的做法是照抄一个能用的**（例如 BaseLib 仓库根目录的 `export_presets.cfg`），再改这两行：

```ini
[preset.0]
name="BasicExport"
platform="Windows Desktop"     # 不能留空
...
[preset.0.options]
binary_format/architecture="msil"   # 纯资源包用 msil
```

### 2.3 清单（`MyMod.json`）

```json
{
  "id": "MyMod",
  "name": "My Mod",
  "author": "you",
  "description": "…",
  "version": "v0.1.0",
  "has_pck": true,
  "has_dll": true,
  "min_game_version": "0.111.0",
  "dependencies": [{ "id": "BaseLib", "min_version": "3.4.7" }],
  "affects_gameplay": true
}
```

- **不要改 `id`**：它决定游戏加载的文件名，也决定本地化路径（见 2.1）。
- `min_game_version` 写你实际测试过的游戏版本。
- `affects_gameplay: true` 表示会做联机一致性检查；纯界面模组才设 `false`。
- 文件必须是 **UTF-8 无 BOM**。中文作者名容易被工具以 GBK 写坏，写完用下面这段验一下：

```powershell
$p = ".\MyMod.json"
$o = [System.Text.Encoding]::UTF8.GetString([System.IO.File]::ReadAllBytes($p)) | ConvertFrom-Json
"OK id=$($o.id) author=$($o.author)"
```

### 2.4 入口点

```csharp
using HarmonyLib;
using MegaCrit.Sts2.Core.Logging;
using MegaCrit.Sts2.Core.Modding;

namespace MyMod;

[ModInitializer(nameof(Initialize))]
public static class MyModEntry {
    public const string ModId = "MyMod";
    private static readonly Logger Log = new(ModId, LogType.Generic);

    public static void Initialize() {
        // ★ 逐个补丁类打，别用 PatchAll()
        var harmony = new Harmony(ModId);
        foreach (var type in typeof(MyModEntry).Assembly
                     .GetTypes()
                     .Where(t => t.GetCustomAttributes(typeof(HarmonyPatch), false).Length > 0)
                     .OrderBy(t => t.FullName, StringComparer.Ordinal)) {
            try {
                var patched = harmony.CreateClassProcessor(type).Patch();
                Log.Info($"Patched {type.FullName} ({patched.Count} method(s)).");
            } catch (Exception ex) {
                Log.Error($"FAILED to patch {type.FullName}.", ex);
            }
        }
    }
}
```

**为什么不用 `harmony.PatchAll()`**：它遇到第一个失败的补丁类就**整体中止**，后面全部静默不生效；
而且 `PatchAll` 会扫到其它程序集的补丁类，容易连带炸。逐个打 + 分别 catch，
一个补丁不兼容不会拖垮整个模组，日志还直接告诉你是哪个类。

## 3. 构建与部署

### 3.1 `build` 与 `publish` 的区别（关键）

| 命令 | 产物 | 什么时候用 |
| --- | --- | --- |
| `dotnet build` | `MyMod.dll` | 只改了 `.cs` |
| `dotnet publish` | `.dll` **+ `.pck`** | **改了任何资源（文本/图片/场景）都必须用它** |

`.pck` 是 Godot 打的资源包；只 `build` 不会重新生成，改了本地化文本不 publish 就**看不到任何变化**。

### 3.2 ★ 游戏运行时会锁住 DLL

```
error MSB3021: 无法将文件 "…\Ascension11.dll" 复制到 "…\mods\Ascension11\Ascension11.dll"。
The process cannot access the file because it is being used by another process.
```

游戏进程持有模组 DLL 的句柄。**必须先完全退出游戏**。
`deploy.ps1` 会先检查 `Get-Process -Name SlayTheSpire2`，并询问是否关闭。

如果改的是日志/资源而游戏还开着，可以先"编译到暂存目录"，等游戏关掉再原子替换：

```powershell
# 把输出目录重定向到别处，游戏锁不到
dotnet publish .\MyMod.csproj -c Debug -p:ModsPath="$env:TEMP\mymodstage\"
# 游戏关闭后
Copy-Item "$env:TEMP\mymodstage\MyMod\*" "<游戏>\mods\MyMod\" -Force
```

### 3.3 本机 PowerShell 执行策略

```
File deploy.ps1 cannot be loaded because running scripts is disabled on this system.
```

两种绕法（任选）：

```powershell
pwsh -ExecutionPolicy Bypass -File .\deploy.ps1
```

或者包一个 `.cmd`（推荐，双击/命令行都能用）：

```bat
@echo off
pwsh -NoProfile -ExecutionPolicy Bypass -File "%~dp0deploy.ps1" %*
exit /b %ERRORLEVEL%
```

### 3.4 安装位置

```
<SlayTheSpire2.exe 所在目录>\mods\<ModId>\<ModId>.dll / .json / .pck
```

`mods` 会被**递归扫描**，所以可以套一层子目录，但保持 `mods/<ModId>/` 最直观。

## 4. 新建模组的检查清单

按顺序做完，每步都有明确的验证方式：

- [ ] `.NET 9 SDK` 就位 → `dotnet --list-sdks` 看到 9.x
- [ ] MegaDot **4.5.1** 就位 → `GodotPath` 指向 `.exe`
- [ ] `Sts2PathDiscovery.props` 能找到游戏 → 报错时在 `local.props` 里显式写 `Sts2Path`
- [ ] BaseLib 已订阅且游戏内**已启用**
- [ ] `<ResourcesDir>` == 模组 id == `MyMod.json` 的 `id` == 工程名
- [ ] `MyMod.json` 是 UTF-8 无 BOM，且能被 `ConvertFrom-Json` 解析
- [ ] `dotnet build` 通过（0 error）
- [ ] `dotnet publish` 通过，`mods/<ModId>/` 下同时有 `.dll` 和 `.pck`
- [ ] 游戏**已关闭**后才部署
- [ ] 启动游戏，日志里能看到 `Loading assembly DLL …` 和你的初始化日志
- [ ] **设置 → 模组设置** 里模组是启用状态

## 5. 常用命令速查

```powershell
# 环境
$env:DOTNET_ROOT = "$env:USERPROFILE\.dotnet"

# 编译（只改代码）
dotnet build   .\MyMod.csproj -c Debug

# 编译 + 打 .pck + 拷进 mods
dotnet publish .\MyMod.csproj -c Debug

# 完整部署（关游戏 + 上面两步 + 断言 .pck）
.\deploy.cmd

# 查看游戏日志（实时）
Get-Content "$env:APPDATA\SlayTheSpire2\logs\godot.log" -Wait -Tail 30
```
