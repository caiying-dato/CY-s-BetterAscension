# A11~A20 游戏落点研究

> 本文件记录进阶 11~20 每一条在游戏内部的**挂载点**，以及支撑它的实测证据。
> 目的是让「改哪一处、为什么是这一处」有据可查，而不是靠猜。
>
> **证据来源**
> - `tools\ApiDump` 在**真实 `sts2.dll`**（v0.111.0，9760 个类型）上的实测 —— 查签名 / IL / 调用者
> - 游戏 `v0.111.0` 的反编译源码 —— 辅助查逻辑（**注意它与真实 DLL 存在若干差异**，见文中的标注）
>
> **标注含义**
> - `[DLL✓]` = 已在真实 DLL 上验证过，**以此为准**
> - `[源码]` = 只从反编译源码读到，未在 DLL 上复核
> - `[待验]` = 尚未定位
>
> 两者冲突时一律以 `[DLL✓]` 为准 —— 本项目中已多次出现"源码写着 A、真实 DLL 里其实是 B"的情况。

### 0.1 上限 `10` 在哪里

`[DLL✓]` `AscensionManager.maxAscensionAllowed`：**`IsLiteral=True`** → 编译期常量，无运行时字段槽位。
反射 `SetValue` 抛 `FieldAccessException` → 从 `ModelDb.Init` 冒到 `NGame.GameStartup()` → **中止启动 + 弹错误框**。
**所以这里从一开始就不该尝试反射写入。**

**而且它是死代码**——全程序集无引用。真正的上限是散落的字面量 `10`，只能改 IL：

| 方法 | 处数 | 作用 |
| --- | --- | --- |
| `ProgressState.ClampAscension` | 3 | 读档时夹取运行局等级 |
| `ProgressState.ClampCharacterStatsFields` | **6** | 夹取 `MaxAscension` / `PreferredAscension`（最易漏） |
| `ProgressSaveManager.IncrementSingleplayerAscension` | 1 | 胜利解锁下一阶 |
| `ProgressSaveManager.IncrementMultiplayerAscension` | 1 | 同上（多人） |
| `UnlockConsoleCmd.UnlockAscensions` | 2 | 控制台解锁 |

`[DLL✓]` 补充：**`AscensionManager._level` 是 `readonly`**（文档只说是 `private`）。
所以构造后无法用反射改等级——等级必须在构造时就正确。

### 0.2 两个"唯一收口点"

`[DLL✓]` **`AscensionManager.HasLevel`** 的完整 IL 只有 5 条：
```
ldarg.0 ; ldfld _level ; ldarg.1 ; clt ; ldc.i4.0 ; ceq ; ret
```
即 `!(_level < (int)level)`。`RunManager.HasAscension` 与 `AscensionHelper.HasAscension` 全部经过它 → **只补它**。

`[DLL✓]` **`CharacterStats.MaxAscension` 有 13 处读取者**（很容易只找到其中一部分）：
```
ProgressState.ClampCharacterStatsFields          ProgressState.MergeCharacterStats
ProgressSaveManager.IncrementSingleplayerAscension
StartRunLobby.BeginRunLocally                    StartRunLobby.SetSingleplayerAscensionAfterCharacterChanged
StartRunLobby.GetMaxAscensionAcrossAllCharacters StartRunLobby.UpdatePreferredAscension
Player..ctor                                     ← 容易漏，玩家构造时就读书存值
UnlockConsoleCmd.UnlockAscensions
NCharacterStats.LoadStats
MegaCritSerializerContext (+<>c, 2 处)           SaveManager.GetAggregateAscensionProgress
```
> 13 处逐点打补丁是不可维护的。**只补 getter**，且**只改返回值不写存档** → 卸载模组后存档完全兼容。

### 0.3 上限是单一常量，不从各处硬编码

上限**不写死**，而是集中在一个常量 `AscensionLevelRegistry.MaxLevel`（当前 20）。
Transpiler、`if (__result < N)`、面板上限全部从这一处取值。
**将来扩到 30 只改这一个数字。**

## A11 · 精英强敌 —— 精英敌人额外获得 1 点力量

| 项 | 值 |
| --- | --- |
| 挂载点 | `MonsterModel.AfterAddedToRoom()` **Postfix** `[DLL✓]` |
| 精英判定 | `RunManager.State.CurrentMapPoint.PointType == MapPointType.Elite`，兜底 `RunState.CurrentRoom.RoomType == RoomType.Elite` |
| 加力量 | ⚠️ **不要用 `ToMutable(int)`** —— 见下方"空引用闭环" |
| **正解** | `var p = ModelDb.Power<StrengthPower>().MutableClone() as StrengthPower; p.ApplyInternal(creature, 1, silent: true);` |
| 状态 | ✅ 已实测生效 |

### `[DLL✓]` 空引用根因闭环（`ToMutable` 的 IL 实录）

`PowerModel.ToMutable(Int32)` 的真实 IL：
```
IL_0007: call      AbstractModel::MutableClone()            ← 先克隆
IL_0014: callvirt  PowerModel::set_CanonicalInstance(...)
IL_001B: callvirt  PowerModel::set_Amount(Int32)            ← ★ 在这里解引用 Owner → 空引用
```

**所以 `ToMutable(int)` 只是 `MutableClone()` 外面套了一层"设数量"。**
克隆体此刻还没有 Owner，`set_Amount` 一解引用就炸。

**正解**：直接用 `MutableClone()` 拿到"数量为 0、无 Owner"的克隆，再让 `ApplyInternal` 一次性完成 设置 Owner → 应用数量 → 挂到生物身上。

### ⚠️ 源码与真实 DLL 的一处分歧

| | 反编译源码 | `[DLL✓]` 真实 DLL |
| --- | --- | --- |
| `PowerModel` 无参克隆 | `ToMutable()` | **不存在**。`PowerModel` 上只有 `ToMutable(Int32)` |
| 无参克隆的真实入口 | — | **`AbstractModel.MutableClone() -> AbstractModel`**（`MemberwiseClone` + `IsMutable=true` + `DeepCloneFields` + `AfterCloned`） |

其他已确认的真实签名：
- `PowerModel.ApplyInternal(Creature owner, Decimal amount, Boolean silent) -> Void` ✅ 纯同步
- `PowerModel.SetAmount(Int32 amount, Boolean silent) -> Void`（另有 `set_Amount`）
- `PowerModel.Amount` / `Owner` 均为**属性**
- `ModelDb.Power<T>() -> T` 是**泛型方法**
- `PowerCmd.Apply<T>(...) -> Task<T>` / `Task<IReadOnlyList<T>>` —— 全是 `Task`，**主线程不可同步等**

> **`MutableClone()` 与 `ToMutable(int)` 的差异**：前者不设 `CanonicalInstance`。
> 实现时要实测确认这一点是否影响"能力变化"通知（`MutableClone()` 与 `ToMutable(int)` 的差别就在这里）。

## A12 · 水土不服 —— 进入新阶段时最大生命值 -6

> ✅ **已解决（借助游戏内遗物/卡牌/药水的官方写法）**

| 项 | 值 |
| --- | --- |
| **换幕触发点** | ✅ `RunManager.EnterNextAct() -> Task` `[DLL✓]` —— 换幕的**单一入口**，由 `ActChangeSynchronizer.MoveToNextAct()` 调用 |
| **减上限的同步内核** | ✅ **`Creature.SetMaxHpInternal(Decimal amount) -> Void`** `[DLL✓]` **纯同步** |
| `[DLL✓]` 它的 IL | `if (amount < 0) throw new ArgumentException("amount must be non-negative.")` → `MaxHp = Math.Min((int)amount, 999999999)` → `CurrentHp = Math.Min(CurrentHp, MaxHp)` |
| **官方先例** | `Player.cs` 自己就调用 `this.Creature.SetMaxHpInternal(player.MaxHp)` `[源码]` |
| ⚠️ **语义是"设绝对值"** | 不是"减 N" → 要写成 `SetMaxHpInternal(creature.MaxHp - 6)`，**且必须自己保证结果 ≥ 0**（负值会让它抛 `ArgumentException`） |
| 作者来源 | `Player.Creature` 是权威存储：`Player.cs` 里 `serializablePlayer.MaxHp = this.Creature.MaxHp`（存档读的是 Creature 的） |
| 幂等保护 | `RunState.CurrentActIndex {get;set;}` / `ActFloor {get;set;}` `[DLL✓]` 可用于"这一幕已扣过"判定 |
| **已确认** | 第 2、3 幕各一次；C# 侧只需在 `EnterNextAct` 触发时对**所有玩家**的 `Creature` 各减 6 |
| 待验 | ⚠️ `EnterNextAct` 返回 `Task`，**Postfix 何时执行**需实测（`MoveToNextAct` 调用它的方式决定）；幂等标记的落点（见下） |

### `[DLL✓]` 关于"幂等标记放哪"的结论

`RunState.ExtraFields`（`ExtraRunFields`）**不是通用扩展字典** —— 它只有三个固定字段：
```
FreedRepy : Boolean      StartedWithNeow : Boolean      TestSubjectKills : Int32
```
不能塞我们的字段。可选方案：
1. **内存态 `HashSet<int>`**（按 `CurrentActIndex`）—— 简单，但**中途存档→重开后可能重复扣**
2. 在 `RunState` 上挂一个 `ConditionalWeakTable` 之类的旁挂表（不随存档）
3. 用 `CardPile`/`Player` 上的可用字段做标记（侵入性大）

> **建议先用方案 1**，并把"重复扣"作为已知限制记录；若实测发现读档会重复触发，再升级方案。

| 项 | 值 |
| --- | --- |
| 类 | `PotionRewardOdds : AbstractOdds`，两个 ctor：`(Rng)` 与 `(Single initialValue, Rng)` `[DLL✓]` |

| **已确认** | 精英房加成 **不跟着降**（`eliteBonus` 保持 0.25） |

### `[DLL✓]` `Roll` 的 IL 还原

```csharp
public bool Roll(Player player, RoomType roomType) {
    float cur = CurrentValue;                                   // 初始 0.4
    if (Hook.ShouldForcePotionReward(player.RunState, player, roomType))
        return true;                                            // ★ 强制时提前返回，连 RNG 都不消耗
    float bonus = (roomType == RoomType.Elite /* = 2 */) ? 0.25f : 0f;
    float threshold = cur + bonus * 0.5f;
    float roll = _rng.NextFloat(1f);
    if (roll < threshold) { CurrentValue = cur - 0.1f; return true;  }
    else                  { CurrentValue = cur + 0.1f; return false; }
}
```

> 原文说的"特殊机制（不掉落会提升概率，掉落会降低概率）"**就是那个 ±0.1**，它本来就在 `Roll` 里 —— **我们不要动它，只改起点 0.4 → 0.3**。

## 13. 设计确认结果（已由 CY 确认，2026-09 定稿）

| # | 问题 | **确认结果** |
| --- | --- | --- |
| 1 | A12「进入新的阶段」 | **第 2、3 幕各一次**（共 2 次，每次 -6 最大生命） |
| 2 | A13 小费范围 | **只对卡牌**（遗物 / 药水不收小费） |
| 3 | A14 手牌上限 | **固定 -1**：原本固定 10 → 变 9。**不是抽牌数**（这是关键更正） |
| 4 | A15 与 A5 的关系 | **A15 激活时 A5 必定激活**（STS2 高阶包含所有低阶）。所以不必处理"A15 单独开"的情况 |
| 5 | A16 价格范围 | **只影响卡牌**（遗物 / 药水不加价） |
| 6 | A17 精英房加成 | **不跟着降**（`eliteBonus` 保持 0.25） |
| 7 | A18/A19 覆盖范围 | **都包含**（被偷袭 / 精英 / Boss 战全部生效） |
| 8 | A20 触发次数 | **每进一次 Boss 战加一张**；随机池**排除 `AscendersBane`** |
| 9 | A11 与 A18 叠加 | ⚠️ **不存在叠加问题** —— **A18 是给玩家的脆弱、A19 是给玩家的虚弱**，与 A11（给精英怪力量）方向完全不同 |

> **第 3、9 条修正了两处重要误读**，连带影响架构：
> - A14 改的是**手牌上限**（一个固定值 10），不是每回合抽牌数。落点完全不同。
> - A18/A19 是**玩家侧 debuff**，与 A11（怪物侧增益）**不是同一个钩子** → 分组方案要重排。

### 13.1 由确认结果推出的"钩子分组"

补丁数量由挂载时机决定，**不按 A11~A20 编号走**：

| 分组 | 时机 | 覆盖条目 | 合并后补丁数 | 同步性 |
| --- | --- | --- | --- | --- |
| **G1 怪物入场** | `MonsterModel.AfterAddedToRoom` Postfix | A11 | 1 | ✅ 同步 |
| **G2 玩家入场** | `CombatManager.AfterCreatureAdded` Postfix + `IsPlayer` | A18、A19 | **1**（强制合并） | ✅ 同步 |
| **G3 换幕** | `RunManager.EnterNextAct` Postfix | A12 | 1 | ⚠️ 方法返回 `Task`，Postfix 时机待实测 |
| **G4 手牌上限** | `CardPile.MaxCardsInHand` getter Postfix | A14 | 1 | ✅ 同步 |
| **G5 商店定价** | `Hook.ModifyMerchantPrice` Postfix | A16 | 1 | ✅ 同步 |
| **G6 购买成功** | `MerchantEntry.OnTryPurchaseWrapper` Postfix | A13 | 1 | ✅ 结果同步可读 |
| **G7 药水掉率起点** | `PotionRewardOdds(Rng)` ctor Postfix | A17 | 1 | ✅ 同步 |
| **G8 卡牌关键词** | `AscendersBane.get_CanonicalKeywords` Postfix | A15 | 1 | ✅ 同步 |
| **G9 Boss 战开始** | 同 G1/G2 时机 + Boss 判定 | A20 | 可与 G2 合并 | ✅ 同步 |

**结论：9 组里 8 组都是干净同步落点，只剩 G3（A12）的 Postfix 时机需要实测确认。**

### 13.2 一个重要模式：优先用"官方钩子"而不是改内部实现

本轮最大的方法论收获 —— 游戏给模组留了正式入口，用它们比改内部实现更稳：

| 需求 | ❌ 改内部实现 | ✅ 官方入口 |
| --- | --- | --- |
| 改商店价格 | `MerchantCardEntry.CalcCost` Postfix（会与打折取整打架） | **`Hook.ModifyMerchantPrice`** |
| 减最大生命值 | `CreatureCmd.LoseMaxHp`（`Task`，主线程不可等） | **`Creature.SetMaxHpInternal`**（同步） |
| 触发换幕效果 | 散落的调用点 | **`RunManager.EnterNextAct`**（单一入口） |
| 加能力 | `PowerCmd.Apply`（`Task`） | **`PowerModel.ApplyInternal`**（同步，A11 已验证） |
| 扣金币 | 手写 `player.Gold -=` | **`PlayerCmd.LoseGold`**（自带 `int.Max(0,…)` 夹取） |
| 手牌上限 | 改 `const` 的 IL | **`CardPile.MaxCardsInHand`** getter |

> **发现方式**：先找"游戏里已经实现了同类效果的遗物/卡牌/药水/事件"，读它们调用了什么 ——
> 那就是官方认可的写法。A12 就是这样定位到 `SetMaxHpInternal` 的（由 CY 提示）。
