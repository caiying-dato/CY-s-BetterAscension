## 2. ★ Mono 版 Godot 需要它自己的运行时目录

**症状**：`Godot_v4.5.1-stable_mono_win64.exe --headless --export-pack ...` 直接崩溃：

```
ERROR: .NET: Assemblies not found
   at: initialize (modules/mono/mono_gd/gd_mono.cpp:647)
CrashHandlerException: Program crashed with signal 11
```

**根因**：只复制了 `Godot_v4.5.1-stable_mono_win64.exe` 与 `..._console.exe` 两个文件。
Mono 版 Godot **还需要同级的 `GodotSharp\` 目录**（内含 `Api\Debug|Release\GodotSharp.dll`、
`GodotPlugins.dll`、`Tools\GodotTools*.dll`，以及 `Tools\nupkgs\` 里的官方 nupkg）。

**修法**：把整个 `GodotSharp\` 一起放到 exe 旁边。现在 `工具\Godot\` 约 221 MB、53 个文件。

> 附带好处：`GodotSharp\Tools\nupkgs\` 里有 `Godot.NET.Sdk.4.5.1.nupkg`、
> `Godot.SourceGenerators.4.5.1.nupkg`、`GodotSharp.4.5.1.nupkg`，
> 可作为 NuGet 还原的离线备用源。

## 3. ★ Windows PowerShell 5.1 按 ANSI 读取无 BOM 的 .ps1

**症状**：`deploy.cmd` 走 `powershell.exe`（5.1）时报一堆语法错误，
错误信息里的中文全是乱码（`娓告垙鐩綍` 之类），报"字符串缺少终止符"。

**根因**：PowerShell **5.1** 对**没有 BOM** 的 `.ps1` 会按**系统 ANSI 代码页（本机 GBK）**
解码。文件其实是 UTF-8，于是中文被解坏，字符串字面量提前截断 → 语法错误。

**修法**：`.ps1` 存成 **UTF-8 with BOM**。PowerShell 7 也认 BOM，所以两边都安全。

> ⚠️ **每次用编辑工具改完 `.ps1` 后都要重新补 BOM**（多数编辑器会写成无 BOM）。
> 补 BOM 的片段：
> ```powershell
> $bom = New-Object System.Text.UTF8Encoding($true)
> $noBom = New-Object System.Text.UTF8Encoding($false)
> [IO.File]::WriteAllText($f, [IO.File]::ReadAllText($f, $noBom), $bom)
> ```
>
> 注意：**`.json` 与 `.cmd` 要保持无 BOM**。游戏对本模组清单/本地化表按 UTF-8 解析，
> 加 BOM 可能出问题；`.cmd` 由 cmd.exe 解析，BOM 会变成乱字符。

## 4. `Copy-Item -LiteralPath "...\*"` 不会展开通配符

**症状**：`Copy-Item -LiteralPath "$src\*" -Destination $dst -Recurse -Force`
**不报错、也不复制**，静默什么都不做。本会话里这个坑踩了两次
（第一次导致 `packages\` 是空的，第二次导致 `docs\A11复盘\` 是空的）。

**根因**：`-LiteralPath` 按字面理解路径，`*` 不再是通配符。二者互斥。

**修法**：用枚举替代通配符：

```powershell
Get-ChildItem -LiteralPath $src -Force | ForEach-Object {
    Copy-Item -LiteralPath $_.FullName -Destination $dst -Recurse -Force
}
```

## 6. `.pck` 导出必须限定范围

`export_presets.cfg` 里 **`export_filter="all_resources"` 会导出项目里的所有资源**，
`exclude_filter` 只影响资源导入扫描、**不阻止打包**。
结果就是 `dist\BetterAscension\BetterAscension.json` 被裹进 `.pck`（功能不受影响，但包体不干净且极难察觉）。

现用配置：

```ini
export_filter="resources"
include_filter="BetterAscension/*"
exclude_filter="dist/*,Code/*,tools/*,packages/*,.godot/*,.git/*"
```

并且 `deploy.ps1` 加了**反向断言**：`.pck` 里出现 `res://dist/` 即报错。

### 已知的无害项：`.godot/global_script_class_cache.cfg`

Godot 会把 `.godot/global_script_class_cache.cfg`（+ `uid_cache.bin`、`project.binary`）
一并打进 `.pck`。**那份缓存文件的内容里含有完整 `res://tools/...`、`res://packages/...` 路径字符串**，
所以：

- ❌ **不要**写"从 .pck 里正则抓 `res://` 路径来判断是否泄漏"的校验 —— 它必然误报。
  （本工程踩过这个坑，浪费了好几轮。）
- ✅ 要用就只查 `res://dist/` 这种"把模组自己又打了一遍"的特征串。
- 实测包内真正有意义的条目只有：
  `BetterAscension/localization/{eng,zhs}/ascension.json` —— 其余都是 Godot 元数据，合计约 1 KB。
- `BetterAscension.json`（模组清单）**在 `.pck` 里是 0 次出现**，正确 —— 它以普通文件形式
  留在 `mods\BetterAscension\` 下，由游戏直接读取。

**手工解析 `.pck` 二进制文件表不值得**：本工程试过按"偏移 112 + 文件数字段"解析，
偏移猜错了、还刷屏了几万字节错误输出。**用 ASCII 子串搜索 + 已知期望路径的正向断言就够了。**
